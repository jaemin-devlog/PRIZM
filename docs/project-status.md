# PRIZM 현재 구현 현황

> PRIZM은 사내 문서를 안전하게 관리하고, 자연어 질문으로 필요한 내용을 찾는 AI 문서 검색 프로젝트입니다.

## 한눈에 보기

지금까지는 **AI 검색이 실제로 가능한지 확인하고, 실제 TXT 문서를 안전하게 등록하는 기반**까지 만들었습니다.

```text
개발 환경 준비
  → 데이터베이스와 벡터 기능 검증
  → Ollama로 실제 임베딩 생성
  → 비슷한 문장을 찾는 검색 API 구현
  → TXT 원본 저장과 QUARANTINED 문서 등록 구현
```

아직 업로드한 문서의 본문을 잘라 임베딩하는 단계는 구현하지 않았습니다. 따라서 현재 검색 대상은 문서가 아니라 검증용 문장 3개입니다.

## 1. 개발 환경 준비

다음 환경을 만들고, 백엔드와 프런트엔드가 각각 빌드되는 것을 확인했습니다.

- Spring Boot 백엔드
- React 프런트엔드
- PostgreSQL 16 + pgvector
- Flyway DB 마이그레이션
- Docker
- Ollama와 `bge-m3` 임베딩 모델

## 2. 데이터베이스와 벡터 기능 검증

AI는 문장의 뜻을 숫자 묶음인 **벡터**로 바꿉니다. PRIZM은 PostgreSQL의 pgvector로 그 숫자를 저장하고 서로 얼마나 비슷한지 계산합니다.

```text
PostgreSQL 실행
  → Flyway로 DB 설정 적용
  → pgvector 활성화
  → vector(1024) 저장
  → cosine 거리로 유사도 비교
```

확인한 결과는 다음과 같습니다.

- DB 컨테이너 상태: healthy
- pgvector: 0.8.2
- 벡터 크기: 1024차원
- 같은 벡터끼리의 cosine 거리: 0

즉, DB가 AI 벡터를 저장하고 비교할 수 있는 상태입니다.

## 3. 실제 AI 임베딩 검증

Ollama의 `bge-m3` 모델로 아래 문장을 숫자로 변환했습니다.

```text
연차 신청은 인사 시스템에서 진행합니다.
  → 1024개의 숫자
```

모델이 실제로 1024차원 벡터를 반환하는 것을 확인했습니다. 따라서 모델의 출력과 DB의 `vector(1024)` 컬럼 크기가 맞습니다.

## 4. 최소 벡터 검색

다음 세 문장을 같은 모델로 임베딩해 DB에 저장했습니다.

1. 연차 신청은 인사 시스템에서 진행합니다.
2. 서버 장애가 발생하면 운영 담당자에게 보고합니다.
3. 기밀 문서는 외부 AI 서비스에 전송할 수 없습니다.

사용자가 다음처럼 질문하면,

```text
휴가는 어디에서 신청하나요?
```

가장 먼저 반환되는 문장은 다음입니다.

```text
연차 신청은 인사 시스템에서 진행합니다.
```

단어가 완전히 같지 않아도 문장의 뜻이 비슷하면 찾을 수 있다는 뜻입니다. 현재 검색 흐름은 다음과 같습니다.

```text
사용자 질문
  → BGE-M3로 질문 임베딩 생성
  → pgvector에서 cosine 유사도 검색
  → 가장 비슷한 문장 반환
  → POST /api/search 응답
```

## 5. 최소 문서 등록

이제 사용자가 실제 TXT 파일을 올릴 수 있습니다.

```text
TXT 파일 업로드
  → 원본 파일을 로컬 저장소에 보관
  → 문서와 첫 버전의 메타데이터를 DB에 저장
  → QUARANTINED 상태로 등록
  → 목록 또는 상세 조회
```

`QUARANTINED`는 “아직 승인되거나 검색 대상으로 전환되지 않은 격리 상태”라는 뜻입니다. 업로드한 파일은 현재 검색 결과에 포함되지 않습니다.

### 문서와 버전을 나눈 이유

```text
보안업무지침 (documents)
├─ 1버전 (document_versions)
├─ 2버전
└─ 3버전
```

나중에 문서가 수정돼도 이전 버전을 남기고, 어떤 버전을 검색에 사용할지 따로 관리할 수 있습니다. 현재 단계에서는 첫 버전만 등록하며 `active_version_id`는 비어 있습니다.

### 파일 저장 방식

파일 본문을 DB에 직접 넣지 않고 로컬 폴더에 저장합니다.

```text
storage/
└─ documents/
   └─ 문서ID/
      └─ 버전ID/
         └─ original.txt
```

DB에는 원본 파일명, 서버 저장 경로, 파일 형식, SHA-256 해시, 상태, 생성 시간을 기록합니다. 파일은 TXT만 허용하고 기본 최대 크기는 10 MiB입니다. 빈 파일, 경로를 조작하려는 파일명, TXT 이외 파일은 거부합니다.

파일 저장 후 DB 저장이 실패하면 남은 파일을 삭제하도록 처리했습니다. 파일 시스템과 DB는 하나의 완전한 트랜잭션이 될 수 없기 때문에, 실패 흔적을 최소화하기 위한 보상 처리입니다.

### 현재 문서 API

- `POST /api/documents`: TXT 문서 업로드
- `GET /api/documents`: 문서 목록 조회
- `GET /api/documents/{documentId}`: 문서와 버전 상세 조회

업로드 직후 응답은 다음과 같은 형태입니다.

```json
{
  "documentId": 1,
  "versionId": 1,
  "title": "보안업무지침",
  "originalFileName": "security.txt",
  "status": "QUARANTINED"
}
```

## 현재 완성된 부분

- Spring Boot와 React 실행 환경
- PostgreSQL + pgvector + Flyway
- Ollama `bge-m3` 1024차원 임베딩
- 벡터 저장과 cosine 유사도 검색
- `POST /api/search`
- TXT 원본 파일 저장
- `POST /api/documents`, 문서 목록·상세 조회
- `QUARANTINED` 문서 버전 등록
- 단위 테스트와 PostgreSQL 통합 테스트

## 다음 개발 단계

다음에는 업로드한 TXT를 실제 검색으로 연결합니다.

```text
QUARANTINED TXT 문서
  → 본문 읽기
  → 긴 내용을 작은 청크로 나누기
  → 청크마다 임베딩 만들기
  → pgvector에 저장
  → 승인·활성화된 버전만 자연어 검색
  → 문서명과 출처를 함께 반환
```

그 이후에는 PDF 지원, AI C/S/O 등급 추천, 관리자 승인, 권한별 검색 제한, 문서 버전 교체, MCP 검색, OpenSQL 장애 복구를 순서대로 추가할 예정입니다.

## 아주 간단한 결론

**지금까지:** AI가 문장의 의미를 숫자로 바꾸고, 비슷한 문장을 실제로 찾는 기능을 완성했습니다.

**현재:** 사용자가 올린 TXT 원본을 안전하게 저장하고, 아직 검색되지 않는 격리 문서로 관리할 수 있습니다.

**다음:** 업로드한 문서를 잘라 임베딩하고, 승인된 실제 문서 내용을 자연어로 검색하게 만듭니다.
